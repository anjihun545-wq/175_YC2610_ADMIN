# 2026 연천피지컬 서바이벌 · 경기 기록관리 v1.4 (Apps Script)

GitHub Pages에서 실행하는 **개인전 001~200번 / 단체전 01~50팀(팀당 4명)** 경기 시간 기록 시스템입니다. 선수 이름·팀 이름 등록이 필요 없습니다.

## v1.4의 달라진 점

- **Firebase 완전 제거:** Google Apps Script + Google Sheets로 서버 변경.
- **로그인 없음:** 운영요원은 경기 화면에서 계측 제어권을 얻고 버튼을 누릅니다. MC는 `?view=mc`에서 결과를 확인합니다.
- **기록 저장 검증:** 종료 즉시 IndexedDB에 기록과 전송 대기열을 함께 보관합니다. 서버가 저장한 요청 ID를 **다음 조회에서 다시 확인한 후에만** `서버 저장 완료` 취급합니다.
- **기록 갱신:** MC 화면은 Apps Script를 약 5초 간격으로 조회합니다. Firebase의 푸시형 실시간 업데이트가 아닙니다. Apps Script 지연에 따라 수초~수십 초 걸릴 수 있습니다.
- **경기 기록 초기화:** 개인전만 / 단체전만 / 전체. JSON 백업 다운로드, 확인 체크, 확인 문구를 요구합니다. 200개·50개 번호 슬롯은 유지됩니다.
- **동시 계측 방지:** 동일 시점에는 한 대의 기기만 제어권을 갖습니다. 시작/종료 타이머 자체는 브라우저의 고정밀 시간으로 계측합니다.
- **안전장치:** 서버 기록 초기화 세대(generation)를 확인해 예전 미전송 기록을 재연결 후 덮어쓰지 않게 합니다. 요청 ID로 중복 쓰기를 막습니다.

## 설치 순서 — 총 2군데

### A. Google Sheets + Apps Script

1. Google Drive에서 **새 Google 스프레드시트**를 만듭니다. 예: `YC2026 경기 기록 DB`.
2. 스프레드시트 메뉴 **확장 프로그램 → Apps Script**.
3. 기본 `Code.gs`를 지우고 이 ZIP의 **`apps-script/Code.gs`** 내용 전체를 붙여 넣어 저장합니다.
4. 함수 선택에서 `setup`을 선택하고 ▶ 실행합니다. Google 계정의 권한 허용을 진행합니다.
5. Apps Script에서 **배포 → 새 배포 → 유형: 웹 앱**.
   - 실행 사용자: **나(소유자)**
   - 액세스 권한: **모든 사용자(Anyone)**
6. 배포 후 제공되는 **`https://script.google.com/macros/s/…/exec` URL 전체를 복사**합니다.
7. 브라우저에서 `웹 앱 URL?action=ping`을 열었을 때 `"ok":true`와 서비스 이름이 출력되는지 확인합니다.

> 무료 Google 개인 계정에서 웹 앱 배포 시 조직 정책 등에 따라 `모든 사용자`가 제공되지 않을 수 있습니다. Google 승인 화면이 나오면 설치 계정에서 권한 승인해야 합니다.

### B. GitHub Pages

1. `js/apps-script-config.js`를 열고 `APPS_SCRIPT_URL = ""`의 따옴표 안에 A-6의 **/exec 링크**를 붙여 넣습니다.
2. ZIP 안의 **전체 파일과 폴더**를 기존 GitHub 저장소 최상위에 올려 동일한 이름을 덮어씁니다. `index.html`은 반드시 루트에 둡니다.
3. 기존 `js/firebase-config.js` 및 `database.rules.json` 파일은 **v1.4에서는 사용하지 않습니다**. 남아 있어도 로딩하지 않지만 혼동을 막기 위해 삭제를 권장합니다.
4. GitHub Pages가 켜져 있는지 확인합니다. 기본 URL: `https://anjihun545-wq.github.io/175_YC2610_ADMIN/`.
5. 다른 기기에서 MC 조회 주소: `https://anjihun545-wq.github.io/175_YC2610_ADMIN/?view=mc`.

## 테스트 순서

1. Google Sheets가 연결되면 서버 상태가 정상으로 바뀌는지 확인합니다.
2. 계측 화면에서 `계측 제어권 획득`을 누릅니다.
3. 개인전 001번 시작 → 종료 → 서버 미전송 `0건`이 될 때까지 기다립니다.
4. **다른 기기의 MC 화면**에 001번 기록이 뜨는지 확인합니다.
5. 단체전 01팀 기록 및 개인전/단체전 개별 초기화를 테스트합니다.
6. 인터넷 연결을 끊었다가 재연결하여 미전송 기록 자동 재시도를 확인합니다.
7. 경기 본편 전에 계측 PC와 MC 휴대폰에서 전체 리허설을 진행합니다.

## 중요한 한계

- Apps Script는 진짜 푸시 방식이 아니므로 **즉시 반영 보장은 불가능**합니다. 화면 조회는 약 5초 주기이고, 서비스 지연·호출량 제한에 따라 느려질 수 있습니다. 공식 기록은 계측 PC 저장을 기준으로 합니다.
- Apps Script 웹 앱을 `모든 사용자`에게 공개하여 계정 로그인을 없앴습니다. **웹 앱 URL을 아는 누구나 기록 열람·수정·초기화 요청을 만들 수 있습니다.** MC 조회 전용 화면도 서버 수준 권한 분리는 아닙니다. 행사 외부에 URL을 알리지 않고, 운영용 비밀번호가 필요한 경우 추후 별도 설계를 권장합니다.
- 기기 내부 저장도 브라우저 데이터 삭제·하드웨어 손상까지 보호하지 못합니다. 결승선 영상, 보조 스톱워치, 정기 CSV/JSON 백업을 병행하세요.
- 200명 + 50팀 로직은 모의 환경에서 시험했습니다. **실제 Apps Script에 연결한 다중 기기 반영, Google 할당량 및 행사장 네트워크 시험은 미완료**입니다.
- Chrome/모바일 브라우저에 따라 Apps Script의 HTML 폼 POST 및 JSONP 응답이 차단될 수 있습니다. 실제 기기에서 반드시 시험하세요.

## 구글 시트에서 결과 직접 보기

`YC_RESULTS` 탭에는 개인전 200행, 단체전 50행이 순서대로 표시됩니다. `YC_META`, `YC_STATE_A`, `YC_STATE_B`는 자동 복구용 내부 데이터이므로 직접 수정하지 마세요. 결과표에서도 기록을 직접 고치지 말고 웹사이트에서 수정·확정해야 서버 기록과 일치합니다.
