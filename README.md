# 2026 연천피지컬 서바이벌 · 경기 기록관리 v1.1

GitHub Pages 웹앱. **개인전 001~200번(200명), 단체전 01~50팀(4명 1팀)**이 사전에 내장되어 있습니다. **선수 등록·팀 등록·CSV 명단 업로드가 필요 없습니다.**

## 현장 계측

1. `경기 계측` → `개인전` 또는 `단체전` 선택
2. 기본 대상(001번 / 01팀)을 확인하거나 **다음/이전, 번호 선택, 번호 바로 이동, 전체 번호판**으로 원하는 번호를 지정
3. 출발과 동시에 **시작**, 도착과 동시에 **종료** 클릭 → 기기에 기록 저장
4. 프로그램이 **다음 미계측 번호로 자동 이동** → 반복
5. 이미 기록된 번호를 다시 시작할 수 없도록 방지. 오류 시 `기록·순위`에서 사유를 입력하여 수정/취소 및 재계측
6. 계주경기는 **4인 1팀이 순서대로 한 팀씩 출발**하여 첫 주자 출발부터 네 번째 주자 도착까지 팀 전체 경과시간 한 개를 기록

## 화면

- `경기 계측`: 종목 전환 / 번호 선택 / 진행 완료 및 대기 집계 / 타이머 / 시작·종료 / DNF / DSQ
- `번호별 현황`: **200명·50팀 전 번호판**, 대기·완료·실격·미완주 색상 표시, 터치해서 계측 화면 이동
- `운영 현황`: 개인전·단체전 별 전체·완료·대기 수, 현재 경기 진행 상황
- `기록·순위`: 종목별 시간 오름차순, 기록 확정·수정
- `MC 화면`: 개인전 및 단체전 TOP 10, 현재 진행 경기 참고용 타이머
- `운영·백업`: Firebase 상태, 전송 대기열, 전체·종목별 기록 CSV 다운로드

## 실시간 동기화

기존 `Firebase Realtime Database` 연결 구조를 유지합니다. Firebase 미연결 시 **기기 내부 체험 모드**로 동작하며 다른 기기에 데이터가 공유되지 않습니다. 실시간 공유는 `js/firebase-config.js`에 설정값 입력 + Firebase Authentication + `database.rules.json`을 Firebase 콘솔에 실제 적용해야 합니다. 자세한 내용은 `docs/SETUP_GUIDE.md` 참조.

고정 슬롯은 웹앱이 자동 생성하므로, Firebase에는 **실제 계측 결과**만 저장됩니다. 브라우저에서 타이머를 측정하며 IndexedDB에 기록 및 미전송 대기열을 보관합니다. 다만 **장애 후 100% 복구 또는 사람의 수동 계측 정확도는 보장되지 않습니다.** 보조 스톱워치와 영상으로 대조하세요.

## 업데이트 안내

v1.0에서 v1.1로 갱신할 때 `index.html`을 비롯한 ZIP 내부 **최상위 파일/폴더 전체를 새 버전으로 덮어쓰세요.** `js/firebase-config.js`를 이전에 실제 Firebase 값으로 수정했다면 업데이트 전 별도 백업하여 새 버전 파일에 그대로 복원하세요. **Firebase 데이터베이스를 초기화하거나 기존 runs를 삭제하면 안 됩니다.**

**이전 v1.0에서 등록한 선수 이름 데이터는 새로운 고정 번호판 화면에 표시하지 않습니다.** 기존 Firebase 기록은 유지되며 기존에 생성된 임의 참가자 ID 기록이 자동으로 001~200번 슬롯에 연결되지는 않습니다. 기존에 실기록이 있으면 마이그레이션이 필요합니다.

## 배포

1. ZIP 해제 후 내부 파일 전체를 저장소 루트에 업로드 (`index.html` 최상단).
2. GitHub 저장소 Settings → Pages → Deploy from a branch → `main` / `(root)` 저장.
3. Pages 사이트에서 체험 모드 테스트.
4. Firebase 연동, 역할 설정, 여러 기기/오프라인 테스트를 마친 뒤 실전에 사용하세요.
